# New York Atlas

Jingheng approved the map-first “Open City” redesign on September 27, 2026. The Atlas is the single interface for films, TV, music and literature. A viewport-filling map, four category choices and search lead to one compact floating card. There are no collection pages, persistent results list, pagination, related-link trails or introductory essay. Complete sources and context remain in a shared native dialog. See `docs/atlas_redesign.md` for the accepted criteria.

All media share one card component, image frame, typography, spacing and action placement. Film stills fill the frame; book and album covers retain their original proportions within the same frame. Music adds only a user-initiated preview. Source catalogs and media are unchanged.

`lib/new_york_atlas.ts` adapts the original catalogs. The browser receives a compact searchable index with original coordinates and source-specific place identities. Markers group only records with the same `place_key`; proximity never establishes identity. A native work selector appears only when the selected place has multiple matching works. The map clusters close pins for navigation without changing their coordinates. Geographic precision and artist-connection labels remain visible on the card, with complete context in the details dialog.

The map uses the existing Leaflet and markercluster dependencies with OpenStreetMap tiles and visible attribution. It does not use a Google SDK or paid API. Keyless Google Maps links preserve the original coordinate helpers. This respects the strict $0 Google integration boundary in `docs/google_maps.md`. Tile failure leaves search, cards and external links usable.

The Atlas owns `medium`, `q` and `entry` URL parameters through `useMapLocation`. A fresh visit has no selected card. Search spans titles, creators and places, intersects the category and shows up to eight transient suggestions. Selecting a pin or result opens one card; closing it keeps the map and filters. Empty or invalid selections show no stale detail. Unrelated URL parameters and hashes survive client navigation.

The old film, music and literary collection routes issue permanent redirects to Atlas. `lib/atlas_legacy.ts` translates valid work/place/passage selections into exact Atlas IDs, preserves unrelated parameters, and removes obsolete navigation state. Legacy routes are absent from the sitemap. Their separate UI components and styles have been removed, while shared catalogs and data validation remain.

`/api/atlas-entry?entry=…` returns one public detail, with unknown IDs returning 404 and release-sensitive responses marked no-store. `useAtlasDetail` caches successful selections, cancels superseded requests and rejects mismatched responses. Loading/failure states never display a previous work as the new selection. Retry and a normal full-page link remain available. Linked first-load and no-JavaScript details render on the server; a no-JavaScript form and source details preserve basic access.

One audio element uses the existing preview hook. Changing places for the same recording retains playback, while another recording or a closed card stops it. Previews never start automatically. The shared source dialog contains the full text, credits, relationship notes and external sources for every medium.

The Atlas static JavaScript budget remains 470,000 raw / 150,000 gzip bytes; the serialized index remains under 160,000 bytes. These are build constraints, not field performance scores. Browser coverage includes common card structure, keyboard and touch navigation, URL/history and legacy redirects, no-JavaScript selections, source metadata, missing media/map tiles, stale detail protection and playback lifecycle. Full cross-browser CI and independent review are required before merge.
